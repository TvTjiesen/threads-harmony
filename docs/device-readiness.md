# 固定候选：设备与官网验收

此流程不依赖网络就能验本机主链。Pura X View 是手机主验；MatePad Edge 负责多窗、键鼠和独立构建。Windows 手机模拟器只作为自动化和布局的基线。每次先记录源码 SHA、已安装构建、系统/API、窗口形态、字号、主题和输入方式；回执分别记录通过、失败、未测。

## 1. 设备复测

使用设备本机的 HDC 完整路径与明确的调试目标。在只含演示数据的设备上，先手动打开首页，确认发现页无现有查询、没有本机帖子遮住预置「折叠屏」结果，也没有给该演示帖追加本机回复。默认命令仅读 API 和安装状态；`--ui` 另外执行本机导航，不安装、不清数据、不改系统设置，也不打开网页。

```powershell
node tools/device-smoke.mjs --hdc '<HDC 绝对路径>' --serial '<本机调试目标>'
node tools/device-smoke.mjs --hdc '<HDC 绝对路径>' --serial '<本机调试目标>' --ui
```

检查：首页 → 发现「折叠屏」 → 回复摘要 → 精确 `s4` → 返回保留查询 → 清除 → 首页。脚本用当前应用树定位，勾选的是语义和操作结果，不替代读屏或键鼠验收。失败后手动清除发现查询并回首页再试；不自动回退应用数据。没有 Node/HDC 的 GUI 环境可照相同步骤手测。不分享目标编号、原始 UI 树、签名或私人内容。

## 2. 真机窗口和无障碍

- Pura X View：各窗口形态在同一演示帖停留，记录折展前后首个可见帖、当前回复、草稿段与附件页；验证系统返回、图片翻页与视频不会自行续播。跨尺寸重点是同一帖，不要求坐标逐像素一致。硬件未连则记未测。
- MatePad Edge：从宽窗连续缩到窄窗，再放开；记录分栏临界点、窗口可用宽度和读位。验证 Tab、Shift+Tab、Enter/Space、系统返回、鼠标滚轮和原生菜单；只用真实键鼠判定硬件行为。
- 读屏：以正文、作者、回复摘要和讨论动作检查焦点、顺序、名称、激活、返回。标准/特大字号、浅色/深色分别查内容、触达区和截断；系统减少动效开启时导航仍须可完成。UI 树只作为辅证，不能代替实际播报。
- 首帧、帧率、PSS 按[性能采样指南](device-performance.md)拆开记录。没有实际设备跟踪不填首帧或掉帧；同进程重复 PSS 只说明采集可用。

## 3. 网络恢复后才验官网

| 顺序 | 入口与操作 | 证据与判断 |
| --- | --- | --- |
| 1 | Pura X View 同一网络，先用系统浏览器手动打开 `https://www.threads.com/`，保持未登录。 | 记首屏是否出现、是否跳转和失败分类；不截账户、查询参数或会话。浏览器失败时不能判 ArkWeb 缺陷。 |
| 2 | 不改变网络或代理，用应用「我的 → 打开 Threads 网页」进入同一官网，测重试、系统返回与系统浏览器兜底。 | 只在浏览器成功而 ArkWeb 失败时隔离嵌入差异；唤起浏览器、超时消失或出现容器都不等于官网加载。 |
| 3 | 网页首屏可用且用户明确同意，再由用户本人登录，测返回、前后台和会话续用。 | ArkWeb 与系统浏览器分别记录。不读取、复制或共享 Cookie；没有成功授权不写“登录通过”。 |
| 4 | 独立验证开发机到 Graph 的 HTTPS，再经[官方只读联调](threads-public-reader.md)测已批准的范围。 | 无授权、关键词、公开用户名、分页分别记结果；只读样本与真实数据分开。浏览器能开不证明 Graph 已通，Graph 的 HTTP 响应也不证明授权成功。 |

本轮只交付这份验收规程，不启代理或开发中转，不获取凭据，不把网页容器当成真实 Threads。
